# K0: Gradle build, generator skeleton, CI

Read first: `AGENTS.md`, ADR-0001, ADR-0004, ADR-0005, `shared/spec/PORT-PLAN.md` phase 0.
Precondition: hub H0 merged (`shared/VERSION` holds a commit, not `pending`).

## Tasks

### K0-01 Gradle build
- Gradle 9.x wrapper with `distributionSha256Sum` in `gradle/wrapper/gradle-wrapper.properties`.
- `settings.gradle.kts`: `rootProject.name = "nepdate-kotlin"`, `include(":nepdate", ":codegen")`.
  `:nepdate-patro` is added in K4-01, `:benchmarks` in K5-02.
- `gradle/libs.versions.toml`: Kotlin 2.4.20, ktlint and detekt plugins, Kover,
  `com.vanniktech.maven.publish` 0.37, Dokka 2, JUnit 5, jqwik 1.10.1, Jazzer 0.30.0
  (`jazzer-junit`), kotlinx-benchmark 0.5.0 (K5), `kotlinx-serialization-json` (codegen only).
  Test and benchmark libraries are only ever `testImplementation` or `:benchmarks` dependencies.
- ktlint and detekt skip `**/*.generated.kt` (the generated tables are long by design).
- `gradle.properties`: `group=io.github.sanamhub`, `version=0.1.0-SNAPSHOT`.
- `nepdate/build.gradle.kts`: `kotlin("jvm")`, `jvmToolchain(17)`, `jvmTarget = JVM_11`,
  `explicitApi()`, `allWarningsAsErrors = true`, `abiValidation()` (ADR-0004 step 5), the publishing
  plugin with the POM from ADR-0005 (no publishing until K5). No dependency besides the Kotlin
  standard library that the Kotlin plugin adds.
- `CHANGELOG.md` with an empty `## [Unreleased]`.

AC:
- `./gradlew build` passes on a clean checkout.
- `./gradlew :nepdate:generatePomFileForMavenPublication` writes a POM whose `<dependencies>` holds
  exactly one entry, `org.jetbrains.kotlin:kotlin-stdlib`.

### K0-02 Generator skeleton (`:codegen`)
- `application` plugin, main class `io.github.sanamhub.nepdate.codegen.MainKt`, `tasks.run` with
  `workingDir = rootDir`.
- Reads `shared/data/calendar/bs-calendar.json` with `Json.parseToJsonElement` (no serialization
  compiler plugin). Fails with a message naming the year if `min_year != 1901`, `max_year != 2199`,
  `epoch` is not `1901-01-01` / `1844-04-11`, a year doesn't have 12 lengths, or a length is
  outside 29..32.
- Writes `nepdate/src/main/kotlin/io/github/sanamhub/nepdate/Calendar.generated.kt` starting with
  `// Generated by :codegen. DO NOT EDIT.`, then `package io.github.sanamhub.nepdate`, and for now
  only `internal const val MIN_YEAR: Int = 1901` and `internal const val MAX_YEAR: Int = 2199`.
  UTF-8, LF line endings, final newline, ktlint-clean.
- `--args=--check`: generate in memory, compare with the file, exit 1 naming the file on any
  difference, write nothing.

AC:
- Running `./gradlew :codegen:run` twice gives identical bytes.
- After a hand edit of `Calendar.generated.kt`, `./gradlew :codegen:run --args=--check` exits non-zero.

### K0-03 `scripts/ci.sh`
Bash, `set -euo pipefail`. Runs the ADR-0004 gates in order, printing each command before it runs,
stopping at the first failure, and ending with exactly one line `ci: N/N gates passed`. Gates
whose tasks don't exist yet are added by the task that creates them: `javaApiTest` in K1-07,
`checkCoreSplit` in K4-04. Kover's 90 % rule is switched on in K1-06, once there is code to cover.

AC: `./scripts/ci.sh` exits non-zero when a `.kt` file is badly formatted (PORT-PLAN phase 0).

### K0-04 GitHub Actions and repository files
Needs hub H3 (the reusable workflows).
- `.github/workflows/ci.yml`: on `pull_request` and push to `main`; `ubuntu-latest`, Temurin 17 and
  21 (`actions/setup-java`), `gradle/actions/setup-gradle`, `gradle/actions/wrapper-validation`,
  runs `./scripts/ci.sh`; job `shared-check` calling the hub's
  `sanamhub/nepdate/.github/workflows/shared-check.yml`. Every action pinned by full commit SHA;
  `permissions: contents: read`; `concurrency` cancels older runs of the same branch.
- `.github/workflows/shared-sync.yml`: the hub's reusable `shared-sync.yml` with
  `regenerate: ./gradlew :codegen:run`, weekly on Tuesday 03:15 UTC and on `workflow_dispatch`.
- `gradle/verification-metadata.xml` from `./gradlew --write-verification-metadata sha256 help`.
- `.github/dependabot.yml`: `github-actions` weekly. Gradle dependencies are updated by hand
  because each update needs the verification metadata regenerated (say so in `CONTRIBUTING.md`).
- `.github/pull_request_template.md` (task IDs, why, how tested, "What to look at first"),
  `.github/ISSUE_TEMPLATE/bug_report.md` (input, expected, actual, library version, JDK or Android
  version), `SECURITY.md` (private advisory, first reply within a week), `CONTRIBUTING.md` (points to
  `AGENTS.md` and the writing-style skill).
- Human tasks: create `sanamhub/nepdate-kotlin`, protect `main` (CI required), create the
  `production` environment, verify the `io.github.sanamhub` namespace (`docs/runbooks/release.md`).

AC: CI green on the first PR.
