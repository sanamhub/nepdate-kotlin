# ADR-0001: Build layout, toolchain, targets and shared data

- **Status:** accepted
- **Date:** 2026-10-06
- **Approved by:** Sanam

## Context

The Kotlin port is a spoke of the NepDate family (hub ADR-0001) and the calendar engine for the
Android app and its Glance widgets (`nepdate-mobile` ADR-0003). It is also the JVM library for Java
and Kotlin servers. The maintained Kotlin alternative is multiplatform, MPL-2.0, depends on
`kotlinx-datetime` and covers BS 1970–2100 (`docs/competitors.md`).

## Decision

1. **Kotlin/JVM only, not Kotlin Multiplatform.** A plain JVM jar runs on Android without an AAR when
   the tables are in code, not in Android resources. iOS uses the native Swift port
   (`nepdate-swift`); a Kotlin/Native framework would add its runtime to every iOS extension. The
   core avoids `java.*` (except `JavaTime.kt`), so a later move to multiplatform is mechanical and
   needs a new ADR.
2. **Toolchain:** Gradle 9.x with the Kotlin DSL and a version catalog (`gradle/libs.versions.toml`),
   Kotlin 2.4.20, JVM toolchain 17, `jvmTarget = 11` (bytecode runs on Java 11+ and on Android).
   `kotlin { explicitApi() }`. Gradle wrapper checked in with its checksum.
3. **Modules:** `:nepdate` (core) and `:nepdate-patro` (the patro: tithi, public holidays,
   events), both published; `:codegen` and `:benchmarks`, never published. `:nepdate-patro` depends
   on `:nepdate` with `api(project(":nepdate"))`. The core never depends on `:nepdate-patro` and
   contains no patro data (hub ADR-0004; checked by `checkCoreSplit`, ADR-0004 step 7).
4. **No dependencies** in the published artifacts besides `kotlin-stdlib`, and `nepdate` for
   `nepdate-patro`.
5. **Shared data:** `shared/` is a read-only copy of the hub's `data/` and `spec/` with
   `shared/VERSION`. CI calls the hub's reusable `shared-check`; the weekly `shared-sync` runs
   `./gradlew :codegen:run`.
6. **Generator:** writes `nepdate/src/main/kotlin/io/github/sanamhub/nepdate/Calendar.generated.kt`
   and `nepdate-patro/src/main/kotlin/io/github/sanamhub/nepdate/patro/Patro.generated.kt`, each
   starting with
   `// Generated by :codegen. DO NOT EDIT.`; `./gradlew :codegen:run --args=--check` fails on drift.
7. **Docs:** Dokka 2 (Gradle plugin v2), HTML published to GitHub Pages; the javadoc jar comes from
   `org.jetbrains.dokka-javadoc` through the publishing plugin.

## Consequences

- Android apps get no `kotlinx-datetime` and need no desugaring; R8 strips what they don't call.
- An app that only converts dates depends on `nepdate` alone and ships none of the patro strings.
- Kotlin/JS, Wasm and Native users are served by the TS, Rust and Swift ports instead.
